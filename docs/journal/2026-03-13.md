# Journal: 2026-03-13

## Breaking Through the Size 10 Wall — Scaling Self-Play Training

### Background

After fixing the scripted-to-self-play handoff bugs (see 2026-03-07), sizes 7 and 8 trained cleanly to level 10. Size 9 initially stalled, but was solved by increasing hyperparameters. Size 10 required both hyperparameter tuning AND a network architecture change — the first time the default MLP wasn't enough.

### Size 9: Hyperparameters Matter

**First attempt** — `--n-steps 2048 --sp-min-steps 200000` (same as sizes 7/8):
- Stuck at level 0 for 11M steps, SP eval win rate oscillating around 32%
- Recovery cycles every ~750k steps with no advancement
- The model could beat scripted opponents easily but couldn't differentiate itself from its own snapshots

**Diagnosis:** Size 9 has 81 cells and ~163-action space. Episodes run ~140 steps. With `n-steps 2048` split across 4 envs, that's only ~3-4 complete games per PPO rollout — too noisy for gradient estimation. And `sp-min-steps 200000` meant the advance/backtrack evaluations happened before the model could meaningfully improve.

**Fix** — `--n-steps 16384 --sp-min-steps 500000`:
- Level 10 at 8.49M steps, clean advancement every 500k steps
- No recovery cycles at all after scripted phase

### Size 10: The Capacity Wall

**First attempt** — Same hyperparameters as size 9 success (`--n-steps 24576 --sp-min-steps 750000`):
- 11M steps, never left level 0
- 9 recovery cycles, SP eval win rate averaging 28-30%
- Even worse than size 9's first attempt — trending downward over time

**Second attempt** — Added `--net-arch 256,256`:
- Still stuck at level 0 after 4M steps
- SP eval win rate averaging 33-38%, max touching 52-58% but never sustaining 55%
- The bigger network helped slightly (33% avg vs 28%) but couldn't clear the advance gate

**Diagnosis:** The model was regularly hitting 52% but couldn't sustain 55%. Two issues:
1. The advance threshold (55%) was marginally too high for this board size
2. 50-game evaluation was too noisy — a few unlucky games could drop 56% to 48%

**Final successful configuration** — `--net-arch 256,256 --sp-advance 0.52 --sp-eval-episodes 100`:
- Level 10 at 11.16M steps
- Clean advancement every 750k steps (exactly at the min-steps floor)
- No recovery cycles once it started climbing

### Scaling Recipe

The pattern that emerged across sizes:

| Size | Cells | Actions | n-steps | sp-min-steps | net-arch | sp-advance | Result |
|------|-------|---------|---------|-------------|----------|------------|--------|
| 2-6  | 4-36  | 9-73    | 2048    | 50k-200k    | [64,64]  | 0.55       | Easy   |
| 7-8  | 49-64 | 99-129  | 2048    | 200k        | [64,64]  | 0.55       | Needed bug fixes |
| 9    | 81    | 163     | 16384   | 500k        | [64,64]  | 0.55       | Needed bigger rollouts |
| 10   | 100   | 201     | 24576   | 750k        | [256,256]| 0.52       | Needed bigger network + lower gate |

Key scaling dimensions:
- **n-steps**: Must contain enough complete episodes for clean gradients. ~30+ games per rollout.
- **sp-min-steps**: Must give the model enough training to meaningfully improve before being evaluated. Roughly scales with board complexity.
- **net-arch**: Default [64,64] compresses 750 input features to 64 neurons — an 11:1 ratio that loses spatial information. [256,256] gives the network room to represent board-level patterns.
- **sp-advance**: At larger sizes, the model struggles to consistently beat its own snapshots by wide margins. 52% still means "better than even" while being achievable.
- **sp-eval-episodes**: More games = less noise. 100 games gives more reliable measurements than 50 when win rates are close to the threshold.

### Memory Impact

The network size increase is negligible in practice:
- [64,64]: ~130k params, 0.5 MB
- [256,256]: ~620k params, 2.4 MB
- The rollout buffer (~89 MB) and framework overhead (~500 MB) dominate

No hardware concerns even on a 4GB swap machine.

### Pool File Dependency Removed

Also removed the requirement for pre-generated JSON pool files. The env now generates simple fallback boards on the fly when no pools exist. The scripted curriculum handles all opponent board generation dynamically, so new sizes can train without any board pool setup.

### Key Takeaway

Scaling RL self-play isn't just "more timesteps." Each board size increase demands proportional increases across multiple dimensions. The model hitting a wall doesn't mean the approach is broken — it means the training configuration no longer matches the problem complexity. Diagnose which knob is the bottleneck: rollout length, evaluation stability, network capacity, or advance threshold.
