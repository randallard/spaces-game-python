# Journal: 2026-03-07

## Size 7 Self-Play Wall — Debugging the Scripted Curriculum Pipeline

### The Problem

Size 7 training hit a wall. Sizes 2-6 all completed scripted curriculum and reached self-play level 10 within 2M steps. Size 7 burned through 3.5M+ steps stuck at self-play level 0 with no progress.

### Root Cause: Two Bugs in the Scripted-to-Self-Play Handoff

The scripted curriculum trains against levels 1-5, then hands off to self-play. That handoff had two bugs that only surfaced at larger board sizes (where self-play is harder and recovery becomes likely):

**Bug 1 — Empty eval candidates.** `_evaluate_against_snapshots()` builds a candidate list from `seed_path` + snapshots up to `window_level`. At level 0 with no seed (the scripted curriculum doesn't pass one), candidates was empty. The function returned early, `_sp_win_rate` stayed `None` forever, and all decisions fell back to `pool_win_rate`.

**Bug 2 — Stale pool_win_rate.** `pool_win_rate` reads from the scripted callback's `phase_history`, which stops updating after scripted levels are cleared. It froze at 0.45 (the last scripted eval). Recovery exit required `pool_win_rate >= 0.55` — a condition that could never be met. The model was stuck in permanent recovery.

Both bugs are invisible at smaller sizes where the model is strong enough to avoid recovery entirely. Size 7 (49 cells, 99-action space, 70 construction steps) is the first size where the model struggles enough to trigger recovery, exposing the dead loop.

### Fixes Applied

1. **Snapshot eval fallback** — When candidates list is empty but snapshots exist, include the first snapshot. Ensures `_sp_win_rate` always gets measured.

2. **Recovery exit uses SP eval WR** — Changed recovery exit gate from stale `pool_win_rate` to `_sp_win_rate` (when available). The SP eval directly measures what matters: can the model beat its own snapshots?

3. **pool_win_rate logging** — TensorBoard `pool_win_rate` now shows `sp_eval_win_rate` when available, instead of the stale scripted value.

4. **Eval episodes bumped to 50** — Default `sp_eval_episodes` increased from 10 to 50 for less noisy measurements on larger boards. Added `--sp-eval-episodes` CLI arg.

5. **Recovery gate lowered to 0.45** — Default `--recovery-win-rate` changed from 0.55 to 0.45. Recovery exit should be easier than level advancement — it just means "try self-play again", not "you're good enough to advance."

### Hyperparameter Adjustments for Size 7

Beyond bug fixes, size 7 needed tuning:

- `--n-steps 8192` (was 2048) — Larger boards mean longer episodes (~350 steps per game). Need more rollout steps so PPO sees complete games before updating.
- `--sp-min-steps 200k` (was 50k) — More time at each level before advancement decisions, reducing noise.
- `--sp-backtrack 0.30` (was 0.40) — Less aggressive backtracking, giving the model more time to stabilize.

### Results

Six failed runs before finding the bugs. The fixed run (MaskablePPO_6) reached self-play level 3 at 1.1M steps with 98% SP eval win rate. Previous runs never got past level 0 in 5M+ steps.

### Other Changes Today

- **Scripted agents made size-agnostic** — All `1-col` binary flips replaced with `(col+1) % board_size` rotation. Trap placement fixed to always use adjacent column. Sizes 2+ all produce valid boards.
- **Level 5 loss-based column rotation** — Previously only reacted to ties (for supermove trigger). Now also rotates column on losses, making it genuinely harder than level 4.
- **Deploy script** — `scripts/deploy-scripted-models --size N` copies level advancement snapshots and best model from `scripted/` to `stage4/more_available_models/` for the inference server.

### Key Takeaway

Stale metrics from phase transitions are silent killers. The training looked active (rewards fluctuating, snapshots accumulating) but the control loop was reading a frozen value. The fix was small (3 lines), but finding it required tracing the full decision chain from TensorBoard metric back through callback code to the data source.
